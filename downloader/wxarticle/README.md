# 微信公众号文章下载

把公众号文章保存成 **PDF** 和**长截图**，纯本地运行，不用登录、不用抓包。一次可以给多篇，共用一个浏览器依次处理，某篇失败不影响其他篇。

文件名形如 `金渐成-为未来撒下种子~-20251202_0847.pdf / .png`（公众号-标题-发布时间），重复下载同一篇会覆盖。

PyQt5 桌面小程序，也可以走命令行。

## 快速开始

```bat
scripts\start_gui.bat
```

把文章链接粘进上面的输入框（可以多行，也可以直接粘「标题 + 链接」混在一起的文字，右上角会显示识别到几个链接），点「开始下载」或按 Ctrl+Enter。结果保存在项目下的 `outputs/`。

下面的表格每篇一行，显示状态、标题、公众号、发布时间和图片数 / 用时；失败的直接写出原因（隐私设置、已删除、环境异常等）。双击一行打开 PDF，右键可以打开截图、所在文件夹、原文或复制链接。「取消」会立刻中断当前这篇，已完成的文件保留。界面会记住输出目录、PDF / 截图开关、截图清晰度和「显示浏览器窗口」。

启动脚本使用项目下的 `.venv`。还没有这个目录时，用 PATH 上的 `python` 创建它，安装 `requirements.txt`，并安装 Playwright 的 Chromium，之后一直用这个环境。已有 `.venv` 但缺少依赖时，脚本会提示安装命令：

```bash
python -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements.txt
.venv\Scripts\python.exe -m playwright install chromium
```

macOS / Linux 用 `scripts/start_gui.sh`。

## 功能

| 环节 | 做法 |
|------|------|
| 打开 | 无头 Chromium，桌面版 Chrome 的 User-Agent，页面骨架加载完就开始，不等所有网络请求结束 |
| 判断 | 同时等「正文出现」和「微信提示页」：隐私设置、已删除、违规、环境异常等提示约 1 秒内直接报出原因，不再干等超时 |
| 图片 | 正文图片的 `data-src` 直接写进 `src` 并发加载，再快速滚动一遍触发其余懒加载内容，最后等所有图片加载完（最多 30 秒）；加载失败的张数会提示 |
| PDF | A4，保留背景色；打印时去掉正文后面的「作者提示 / 上一篇下一篇」、二维码和推荐区 |
| 截图 | 只截正文栏（标题到正文结束），2 倍像素，字迹清晰；超过 32000 像素高时自动降为 1 倍，仍然超长就拆成 `_1.png`、`_2.png`… |
| 批量 | 多个链接、或 `-f` 指定链接文件；从「标题 + 链接」混合文本里自动抠出链接并去重 |

## 命令行

在项目目录下用 `.venv\Scripts\python.exe` 运行（下面简写为 `python`）：

```bash
python -m backend "https://mp.weixin.qq.com/s/xxxx"                    # 单篇，PDF + 截图
python -m backend "链接1" "链接2" --pdf-only                            # 多篇，只要 PDF
python -m backend -f links.txt -o D:\文章                              # 从文件读链接，指定输出目录
python -m backend                                                     # 不给链接时提示粘贴
python -m frontend                                                    # 图形界面（同 start_gui.bat）
python scripts/probes/probe_article.py "链接"                           # 只探测能不能抓，不保存
```

| 参数 | 说明 | 默认值 |
|------|------|--------|
| `URL ...` | 文章链接，可以多个；不给且没有 `-f` 时提示粘贴 | — |
| `-f/--file` | 链接文件，每行一个，`#` 开头的行忽略 | — |
| `-o/--output` | 输出目录 | 项目下的 `outputs/` |
| `--pdf-only` / `--screenshot-only` | 只生成其中一种 | 两种都生成 |
| `--scale` | 截图像素倍率，1 的文件约小 2/3 | 2 |
| `--show` | 显示浏览器窗口，遇到「环境异常」验证时可以手动处理 | 关 |

长链接（`?__biz=...&mid=...`）在命令行里必须加引号，否则 `&` 会被 cmd 当成命令分隔符；图形界面或提示粘贴时不受影响。超时、截图倍率和高度上限、微信提示语都在 `backend/config.py`。

全部成功返回 0，有失败返回 1，方便在脚本里判断。

## 实测记录

2026-10-25（同一篇 3500 像素高的文章）：

| | 旧版 | 现在 |
|---|---|---|
| 用时 | 19.9 秒 | 5.5 秒 |
| 截图 | 1280 宽整页，正文只占中间一半 | 1450 宽（正文栏 2 倍），约 1MB |
| 打不开的文章 | 等 30 秒后报英文超时 | 约 1 秒报出「根据作者隐私设置，无法查看该内容」 |

金渐成的多数文章设置了「仅微信内可看」，浏览器打开就是隐私提示页，这种只能在微信里看，工具无能为力。短时间内连续打开十几篇会触发「环境异常」，隔几分钟再试即可。

本地仿造页面覆盖了：40 张懒加载图片的长文（总高 4 万像素，自动拆成两张截图，接缝不丢像素）、正文延迟显示、底部悬浮栏、坏图、隐私提示页、永远等不到正文、标题含表情和非法文件名字符、批量中途失败、未安装 Chromium。图形界面另外测了链接识别与校验、成功 / 失败行的显示和右键菜单、保存长文时取消（约 2 秒停下，不残留浏览器进程）、记住设置。

## 踩过的坑

1. **截图只截得到视口里的内容**：`clip` 超出视口的部分会被裁掉，旧版因此把视口拉到整页高。但 Chromium 单张截图约 6.6 万物理像素以下才正常，再往下全是白的，所以超长文章改为分段：每段把视口设成这段的高度、滚过去再截。
2. **截图坐标要取整**：标题位置带小数，分段截图时每个接缝会丢 1 像素，所以截图区域统一向外取整。
3. **`networkidle` 很慢**：公众号页面一直有统计请求，等网络空闲要多花十几秒，而且等不到也不报错，所以改为页面骨架加载完就开始，再显式等正文。
4. **隐私提示页没有 `#js_content`**：旧版只等正文，打不开的文章都要干等 30 秒才失败，而且看不出原因。
5. **PDF 末尾的杂项和空白页**：正文后面的作者提示、上一篇下一篇会打进 PDF，外层容器的下边距还可能把末尾挤出一张空白页，所以只在打印样式里隐藏这些、清掉下边距，不影响截图。
6. **底部悬浮栏盖住正文结尾**：部分公众号（如「分红养老之路」）有固定在页面底部的「赞 / 分享 / 推荐 / 写留言」栏，视口拉到正文高度后它正好压在最后几行上。截图和打印前把正文以外的 fixed / sticky 元素设为透明（不用 `display:none`，免得 sticky 元素让排版跳动）。

## 项目结构

```
downloader/wxarticle/
├── backend/
│   ├── config.py      # 输出目录、User-Agent、超时、截图倍率与高度上限、微信提示语
│   ├── fetcher.py     # 打开文章、识别提示页、取标题 / 公众号 / 发布时间、加载图片
│   ├── generator.py   # 文件命名、PDF、正文栏长截图（超长自动分段）
│   ├── core.py        # 批量流程（一个浏览器逐篇处理）、链接识别，命令行和界面共用
│   └── cli.py         # 命令行（python -m backend）
├── frontend/
│   └── gui.py         # PyQt5 图形界面（python -m frontend），后台线程跑 asyncio，可随时取消
├── scripts/
│   ├── start_gui.bat / start_gui.sh
│   └── probes/        # 文章探测（只打开不保存）
├── outputs/           # 生成的 PDF 和截图（已 gitignore）
└── requirements.txt
```

## 局限

- 设置了「仅微信内可看」的文章打不开（见实测记录）。
- 留言、阅读量、点赞数拿不到，原因见下面的调研备忘。
- 文章里的视频、音频不会下载，小程序卡片、投票等互动组件按网页上的静态样子保存。
- 图片超过 30 秒还没加载完会带着空白继续保存，并提示有几张没加载出来。

## 调研备忘（2026-06-05）

调研了 mptext.top / wechat-article 这套方案，评估能否扩展成"输入链接 → 公众号登录 → 下载整篇文章含留言"的应用。结论记录如下，方便后续决策。

### 三类能力的实现路径

1. **正文下载（本项目现状）**：Playwright 渲染文章页 → PDF/截图，纯本地、无需登录、无需抓包。已够用。
   - HTML+本地图导出：存储占用和 PDF 一个量级（都被图片主导，省不了空间），价值在"可编辑/可转格式/可二次加工"而非体积。仅"看/打印"则没必要加。

2. **整号批量枚举**：需扫码登录 `mp.weixin.qq.com` 后台（`getqrcode`→`scan`→`bizlogin`），再用 `searchbiz`/`appmsgpublish` 接口翻页枚举文章。原理是借公众号后台"写文章时可搜索其他公众号文章"的功能。**单独一摊活，且后台有严格频控/风控风险**，需做缓存与限速。

3. **留言 / 阅读量下载（硬门槛）**：留言走 `mp.weixin.qq.com/mp/appmsg_comment?action=getcomment`，强制要求 `key`/`uin`/`pass_ticket`/`__biz` 这组**手机 App 会话凭证**。
   - 公众号后台登录拿不到，链接里也没有，**只能用 mitmproxy 抓包**（手机 WiFi 代理指向电脑 → App 打开文章 → 拦截响应里的 Set-Cookie/凭证）。
   - 凭证 **~30 分钟失效**，且**只对当时打开的那个公众号 `__biz` 有效**，换公众号要重抓。绕不开"手机+代理"，除非用商业版高速通道。
   - 这也是本项目及同类工具下不了留言的根本原因。
